# Working habits

1. Before changing anything, read the relevant files and follow the existing style.

2. If the task has more than two steps, write a short plan first.

3. If the request is ambiguous, ask one clear question before starting.

4. After the change, run the tests or the code. Report what you ran and the result.

5. Ask before deleting files, force-pushing, or changing config outside the project.

6. Never write secrets or API keys into files.

7. End with a short summary: what changed, what to check.
